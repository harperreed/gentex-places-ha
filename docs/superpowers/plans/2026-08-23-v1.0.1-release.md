# Gentex PLACE v1.0.1 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish an immutable `v1.0.1` patch release whose higher manifest version makes HACS offer an update to installations that already report `1.0.0`.

**Architecture:** Keep integration behavior and dependencies unchanged. Update the three synchronized version sources, add patch release notes, point current README install and upgrade steps at `v1.0.1`, and let the existing protected version-change workflow build and publish the release.

**Tech Stack:** Python 3.14.2, uv, pytest, Home Assistant 2026.8.1, HACS, GitHub Actions.

## Global Constraints

- Change no integration behavior or dependency pins.
- Keep `v1.0.0`, its tag, notes, and assets unchanged.
- Set project, manifest, and lock metadata to exactly `1.0.1`.
- Keep the historical README statement that `v1.0.0` is the first stable release.
- Publish nothing to PyPI and make no HACS default-store submission.
- Reach protected `main` only through a squash-merged pull request with `test`, `hassfest`, and `hacs` green.
- Use the existing automated release workflow; never move a tag or replace a published asset.

- [ ] **Step 6: Verify the public release without credentials**

Run:

```bash
set -eu
main_sha=$(gh api repos/harperreed/gentex-places-ha/branches/main --jq .commit.sha)
tag_sha=$(gh api -H 'X-GitHub-Api-Version:2026-03-10' repos/harperreed/gentex-places-ha/git/ref/tags/v1.0.1 --jq .object.sha)
release_target=$(gh release view v1.0.1 --repo harperreed/gentex-places-ha --json targetCommitish --jq .targetCommitish)
test "$main_sha" = "$tag_sha"
test "$main_sha" = "$release_target"

public_check_dir=$(mktemp -d "${TMPDIR:-/tmp}/gentex-v1.0.1-public.XXXXXX")
case "$public_check_dir" in
  "${TMPDIR:-/tmp}"/gentex-v1.0.1-public.*) ;;
  *) exit 90 ;;
esac
cleanup_public_check() {
  rm -rf -- "$public_check_dir"
}
trap cleanup_public_check EXIT HUP INT TERM
curl --fail --silent --show-error --location --proto '=https' --tlsv1.2 --output "$public_check_dir/gentex_place.zip" https://github.com/harperreed/gentex-places-ha/releases/download/v1.0.1/gentex_place.zip
curl --fail --silent --show-error --location --proto '=https' --tlsv1.2 --output "$public_check_dir/gentex_place.zip.sha256" https://github.com/harperreed/gentex-places-ha/releases/download/v1.0.1/gentex_place.zip.sha256
(
  cd "$public_check_dir"
  sha256sum --check gentex_place.zip.sha256
)
git clone --quiet --branch v1.0.1 --depth 1 https://github.com/harperreed/gentex-places-ha.git "$public_check_dir/repo"
(
  cd "$public_check_dir/repo"
  uv run python scripts/build_release.py --verify "$public_check_dir/gentex_place.zip"
  uv run python scripts/build_release.py --output dist/gentex_place.zip
  cmp -- dist/gentex_place.zip "$public_check_dir/gentex_place.zip"
  cmp -- dist/gentex_place.zip.sha256 "$public_check_dir/gentex_place.zip.sha256"
)
```

Expected: `main`, `refs/tags/v1.0.1`, and the release target have the same SHA; anonymous checksums and archive verification pass; and a clean public tag checkout rebuilds both assets byte-for-byte.
